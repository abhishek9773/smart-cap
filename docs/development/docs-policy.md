# Documenting new features

Keep these pages aligned with implemented code and test evidence. For every
future feature documentation update:

1. Inspect the implementation and the relevant test code or test records.
2. Confirm the behavior that actually ran; do not document a passing test if
   it did not run.
3. Update only the relevant guide pages and any affected navigation entries.
4. Record measured values with the test context and limitations.
5. Mark planned or unverified behavior explicitly.
6. Keep hardware values tied to the board configuration and observed logs.

Firmware changes are outside the scope of a documentation-only update unless
they are explicitly requested as a separate task.

Do not describe proposed AI, distance-estimation, speech, or navigation
features as complete until they have been implemented and verified.
